Core Player Class (UE5 Survival Game)

This artifact is the core class behind an Unreal Engine 5 survival game. The purpose of this class is to handle player movement and interaction within the game, including systems like building, hunger, health, and integration with UI elements. This file was created during my GAM-312 class around May 2026 and later enhanced for the CS-499 portfolio.

Why This Artifact Was Selected

I chose this artifact because it demonstrates key components of software design and engineering. It showcases a complex class with multiple responsibilities and involves algorithmic design in areas such as line traces, grid snapping, and overlap collision queries. The enhancements demonstrate improved use of algorithmic principles and software engineering practices by creating a more modular, maintainable, and readable codebase.

Key Code Improvements

Refactored Building Placement

  • Moved the complex building preview logic outside of the Tick function
  • Created a new dedicated function for the building preview
  • Created clear steps between the line trace, grid snap, and collision check
  • Reduced the amount of unnecessary work performed every frame
  • Added more null checks

FindObject() Refactor

  • Broke down the larger function into smaller helper functions
  • Separated resource harvesting logic from building logic
  • Improved readability and maintainability
  • Removed duplicate code

Default Values Setup

  • Centered the default values into one place within the constructor
  • Set up default values for player stats, traces, and grid sizes
  • Removed unneeded resource variables

Better Stamina/Health Clamping

  • Made sure values could not go below 0 or above 100
  • Replaced manual if statements with clamps
  • Improved readability of player stats while reducing the risk of bugs

Reflection

One key lesson was the importance of separation of concerns. Functions such as Tick() and FindObject() were doing too much. I separated these into smaller, more focused functions that improved readability and maintainability. A major challenge was ensuring that the changes remained compatible with the existing classes and blueprints within the game while still making the code more maintainable.
